UC-01: Manage User Accounts and Roles

Member: Rayyan M.R.M. -- IT25101420

Primary Actor:
Library Administrator

Supporting Actor:
Library Member, Librarian (for self-service registration and profile updates, per Requirements
Section 7.1)

Goal:
Create, update, deactivate user accounts, and assign correct roles; and allow members and
librarians to self-register and manage their own profile information.

Preconditions:
  · The Library Administrator is logged in.
  · The Library Administrator has permission to manage user accounts.
  · For self-service actions, the Library Member or Librarian has a valid account or is registering a
      new one.

Main Flow - Administrator Manages Accounts:
  · The Library Administrator selects "User Management".
  · The system displays the user-account list.
  · The Library Administrator selects an existing user or chooses to create a new user.
  · The Library Administrator enters or updates user information.
  · The Library Administrator assigns a role such as Library Member, Librarian, Finance Officer, or
      Library Administrator.
  · The Library Administrator saves the changes.
  · The system validates the entered details.
  · The system creates or updates the user account.
  · The system displays a success message.

Main Flow - Self-Service Registration and Profile Update:
                                                                                                                                      SE2030 - Software Engineering

  · The Library Member or Librarian selects "Register" or "My Profile".
  · The user enters or updates their personal information.
  · The user saves the changes.
  · The system validates the entered details.
  · The system creates or updates the account within the permissions allowed for that role.
  · The system displays a confirmation message.
Alternative Flows:
  · If required information is missing, the system requests the user to complete it.
  · If the username or email already exists, the system displays an error.
  · If the Library Administrator deactivates an account, the system prevents that user from

      logging in.
  · A Library Member or Librarian cannot change their own assigned role; only the Library

      Administrator can assign or change roles.
Postconditions:

  · The user account is created, updated, or deactivated.
  · The assigned role determines the user's system access.

UC-03: Borrow and Return Books

Member: Wijegunawardana P.K.D.S.U. -- IT25102574

Primary Actor:
Librarian

Supporting Actor:
Library Member, Academic Staff Member (for renewal)

Goal:
Issue available books to members and record returned books.

Preconditions:
  · The Librarian is logged in.
  · The Library Member has an active account.
  · The selected book is available for borrowing.
  · The Library Member has not exceeded the borrowing limit and has no unpaid borrowing
      restriction.

Main Flow - Borrow Book:
  · The Librarian selects "Issue Book".
  · The Librarian searches for and selects the Library Member.
  · The system displays the Library Member's borrowing eligibility.
  · The Librarian searches for and selects an available book.
  · The system checks book availability.
  · The system calculates the due date according to library rules.
  · The Librarian confirms the transaction.
  · The system records the borrowing transaction.
  · The system changes the book status to unavailable or reduces the available-copy count.
  · The system displays the due date and confirmation.

Main Flow - Return Book:
  · The Librarian selects "Return Book".
  · The Librarian enters or searches for the borrowing record.
  · The system displays the borrowed book and due date.
  · The Librarian confirms the return.
  · The system calculates an overdue fine, if applicable.
  · The system updates book availability.
  · The system records the return transaction.
  · The system displays a confirmation and fine amount, if applicable.

Main Flow - Renew Book:
                                                                                                                                      SE2030 - Software Engineering

  · The Library Member selects "Renew Book".
  · The system displays the current borrowed book and due date.
  · The system checks whether another member is waiting (reservation) for the same book.
  · If no one is waiting, the system extends the due date according to library rules.
  · The system updates the borrowing record.
  · The system displays the new due date and confirmation.
Alternative Flows:
  · If the book is unavailable, the system does not allow issuing it.
  · If the Library Member has outstanding restrictions, the system prevents borrowing.
  · If a fine exists after a return, the system sends the fine record to Fine Management.
  · If another member has an active reservation on the book, the system does not allow renewal.
Postconditions:
  · The borrowing or return transaction is recorded.
  · Book availability and the Library Member's borrowing history are updated.

UC-04: Manage Book Reservations

Member: Wijewickrama S.N. -- IT25100467
Primary Actor:
Academic Staff Member (a type of Library Member)
Supporting Actor:
                                                                                                                                      SE2030 - Software Engineering

Librarian
Goal:
Reserve an unavailable book and manage the reservation waiting list fairly.
Preconditions:

  · The Academic Staff Member is logged in.
  · The selected book is currently unavailable.
  · The Academic Staff Member has an active account.
Main Flow:
  · The Academic Staff Member searches for a book.
  · The system displays that the book is unavailable.
  · The Academic Staff Member selects "Reserve Book".
  · The system checks whether the Academic Staff Member already has an active reservation for

      the same book.
  · The system adds the Academic Staff Member to the reservation waiting list.
  · The system displays the reservation status and queue position.
  · When a copy becomes available, the system notifies the next eligible Academic Staff Member

      in the waiting list.
  · The Librarian confirms the reserved-book allocation when the Academic Staff Member collects

      it.
Alternative Flows:

  · If the book is available, the system suggests borrowing it instead of reserving it.
  · If the Academic Staff Member already reserved the same book, the system displays an error.
  · The Academic Staff Member may cancel the reservation before allocation.
  · If the Academic Staff Member does not collect the book within the allowed period, the system

      cancels the reservation and offers it to the next eligible person in the waiting list.
Postconditions:

  · The reservation status and waiting list are updated.
  · The next eligible person receives priority when the book becomes available.

UC-05: Manage Fines and Fine Payments
                                                                                                                                      SE2030 - Software Engineering

Member: Vithanage C.B. -- IT25102212

Primary Actor:
Finance Officer

Supporting Actor:
Librarian

Goal:
View overdue fines, verify automatically calculated fine amounts, record payments, and update
payment status.

Preconditions:
  · The Finance Officer is logged in.
  · A Library Member has an overdue-book fine or an existing unpaid fine record.

Main Flow:
  · The Finance Officer selects "Fine Management".
  · The system displays outstanding fine records.
  · The Finance Officer searches for a Library Member or selects a fine record.
  · The system displays borrowing details, overdue days, calculated fine amount, and payment
      status.
  · The Finance Officer verifies the fine amount.
  · The Library Member makes the payment.
  · The Finance Officer records payment information.
  · The system updates the payment status to paid or partially paid.
  · The system stores the payment transaction.
  · The system displays a payment confirmation.

Alternative Flows:
  · If no unpaid fine exists, the system displays "No outstanding fines".
  · If the entered payment amount is less than the fine amount, the system records a partial
      payment and retains the remaining balance.
  · If the calculation is incorrect, the Finance Officer refers the record for correction before
      accepting payment.

Postconditions:
  · Fine and payment records are updated.
  · The Library Member's outstanding balance is accurate.

UC-06: Manage Fine Appeal and Waiver

Member: Vithanage C.B. -- IT25102212
Primary Actor:
Library Member
Supporting Actor:
Finance Officer, Library Administrator
Goal:
Allow members to submit a fine appeal with a reason and view its status, and allow administrators
to approve or reject the appeal, reduce or waive the fine, and record the decision.
Preconditions:

  · The Library Member is logged in.
  · The Library Member has an existing unpaid or disputed fine.
Main Flow:
  · The Library Member selects "Appeal Fine" for a specific fine record.
  · The Library Member enters the reason for the appeal.
  · The Library Member submits the appeal.
  · The system records the appeal with a "Pending" status.
  · The Library Administrator, in consultation with the Finance Officer, reviews the appeal.
  · The Library Administrator approves or rejects the appeal.
  · If approved, the system reduces or waives the fine amount.
  · The system records the decision and any comments.
  · The system updates the appeal and fine status.
  · The system notifies the Library Member of the outcome.
Alternative Flows:
  · If the appeal is rejected, the fine remains payable in full.
  · The Finance Officer may refer a disputed calculation for correction before a decision is made.
  · The Library Member may view the appeal status at any time.
Postconditions:
  · The fine appeal record and decision are stored.
                                                                                                                                      SE2030 - Software Engineering

  · The fine amount and status reflect the administrator's decision.
